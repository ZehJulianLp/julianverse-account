MEINE APPS

Deine App mit Julianverse

Eine statische Webapp mit lokalem Speicher, optionaler Anmeldung und ausdrücklich aktiviertem ownCloud-Sync.

1. Registrieren und starten

  1. Unter „Meine Apps“ Name, Adresse und einen Callback wie https://deine-app.example/account-callback.html eintragen.
  2. Datenarten anlegen, zum Beispiel notes, projects und settings.
  3. Die Beispiel-App herunterladen. Die ZIP-Datei bildet die registrierten URL-Pfade ab; ihren Inhalt in den Webroot deiner Domain kopieren.
  4. Die App öffnen und zunächst lokal ausprobieren. Im Testmodus kann sich nur dein Konto anmelden.
  5. Im Account die gewünschten Datenarten freigeben und in der App die erste Übertragungsrichtung wählen.

Für einen lokalen Versuch kannst du im Testmodus beispielsweise http://localhost:8000/ und http://localhost:8000/account-callback.html registrieren und die ZIP-Dateien mit python3 -m http.server 8000 --bind 127.0.0.1 ausliefern.

2. In deine Oberfläche einbauen

Die Vorlage enthält alle Module lokal. Es gibt keinen Client-Schlüssel im App-Code.

import { createJSONAdapter, mountAccount } from './account/sdk.mjs';
import { config } from './account/config.mjs';

const data = createJSONAdapter(config);
data.set('notes', { text: 'Meine erste Notiz' });
const notes = data.get('notes');

mountAccount({
  root: document.querySelector('#account'),
  config,
  adapter: data,
  onApply: resource => render(resource, data.get(resource))
});

Füge account/panel.css hinzu. set() speichert zuerst lokal und meldet die Änderung an einen gegebenenfalls aktiven Sync. Anmeldung allein startet keine Übertragung. onApply wird nach einem Cloud-Import aufgerufen.

Für vorhandene Speicherformate kannst du einen eigenen Adapter mit resources, keys, labels, snapshot, validate, backup, backupKey und apply an mountAccount übergeben. Änderungen meldest du mit dem Ereignis julianverse:change und detail.key.

3. Dateien und Konflikte

Die Daten liegen in der ownCloud des angemeldeten Nutzers unter Julianverse/APP-ID/DATENART.json. Eine App kann nur auf ihre eigenen, ausdrücklich freigegebenen Datenarten zugreifen. Das eigene Konto stellt kein Speicherbudget für andere Nutzer bereit.

Bis zu zehn Datenarten, 512 KiB pro JSON-Datei. Das SDK verwendet {"schemaVersion":1,"data":{"value":…},"deleted":false}. Gleichzeitige Änderungen werden über ETags erkannt. Der Account-Bereich bietet beide Versionen zum Download und eine ausdrückliche Auswahl an. Vor einem Import wird eine lokale Sicherung angelegt.

Die API bietet GET /api/sync/APP-ID für Freigaben sowie GET und PUT /api/sync/APP-ID/DATENART. Schreibzugriffe benötigen If-Match mit dem gelesenen ETag oder If-None-Match: * beim erstmaligen Erstellen. Zugriff erfolgt mit einem kurzlebigen Bearer-Token mit Scope sync.

4. Teilen und betreiben

Wähle „Per Link teilbar“ und schalte den Testmodus aus, wenn andere Nutzer die App ausprobieren sollen. Der App-Link erklärt, von wem die App stammt und welche Datenarten sie anbietet. Jeder Nutzer bestätigt Anmeldung und Sync getrennt.

Geänderte Rücksprungadressen und Zugriffsregeln widerrufen bestehende Zugänge. Deaktivierte oder gelöschte Apps erhalten keine weiteren Tokens. Nutzer verwalten ihre eigenen Dateien weiterhin unter „Apps & Zugriff“.

Browser-Sitzungen verwenden sichere HttpOnly-Cookies. Bei externen Domains können Browser Drittanbieter-Cookies blockieren; dann ist nach Neuladen oder Ablauf des kurzlebigen Zugangs erneut „Mit Julianverse anmelden“ nötig. Das bestehende Account-Login kann dabei weiterverwendet werden. Lokale Daten und die gespeicherte Sync-Auswahl bleiben erhalten.

OAuth-Callbacks müssen als HTML ausgeliefert werden, Cache-Control: no-store und Referrer-Policy: no-referrer erhalten und aus Zugriffslogs sowie Service-Worker-Caches ausgeschlossen sein. Nutze für Code fremder Entwickler getrennte Origins. Der Browser muss Popups für die Anmeldung zulassen.
